# DKNet.SlimBus.Generators

A Roslyn incremental source generator, sibling to `DKNet.EfCore.DtoGenerator`, that emits a full CRUD
vertical slice — request records, SlimBus handlers, and (optionally) minimal-API endpoint registration —
from `[CrudCreate]`/`[CrudUpdate]`-attributed entity members. The only hand-written feature code is the
entity method itself; everything else is generated at compile time into the consuming project.

## When to reach for it

Use this package when you already have (or want) `DKNet.EfCore.Specifications` + `DKNet.SlimBus.Extensions`
wired up (aggregates with domain-event-raising methods, dispatched through a SlimBus command pipeline that
auto-saves), and most of your write endpoints are plain "create one, update one field" CRUD — the case where
hand-writing a request record, a handler, and an endpoint mapping per operation is pure repetition.

If your writes have real orchestration (multi-entity transactions, external calls, conditional branching),
write those by hand as ordinary SlimBus features — the generated and hand-written styles are the same shape,
so mixing them on the same entity is seamless (see [Overrides](#overrides--hand-written-handlers-win)).

## Install and minimum wiring

```xml
<ItemGroup>
  <PackageReference Include="DKNet.SlimBus.Generators" Version="{latest}" PrivateAssets="all" OutputItemType="Analyzer" />
</ItemGroup>
```

The generator only *emits* source; the consuming project still needs, at runtime:

- **`DKNet.SlimBus.Extensions`** — the request/handler contracts (`Fluents.Requests.IWitResponse<TDto>`,
  `IWithKey<TKey>`, `IHandler<TRequest, TResponse>`), `NotFoundError`, and the LazyMapper
  (`LazyMapExtensions.ResultOf`) the generated handlers call.
- **`DKNet.EfCore.Specifications`** — `IRepositorySpec` for persistence, and the `Specification<TEntity>`
  base type the generated by-id lookup for update handlers derives from. (Not `DKNet.EfCore.Repos` — that
  package is retired, superseded by Specifications.)
- **`DKNet.AspCore.Extensions`** — only if you want the generated endpoint-registration file; see
  [Endpoint emission is opt-in](#endpoint-emission-is-opt-in).
- **`Mapster`** (namespace `MapsterMapper`) — the `IMapper` implementation generated handlers inject.

Generated files use C# 14 extension-member syntax, so the consuming project's `LangVersion` must be `14` or
later.

Minimum registration to get a generated slice dispatching and auto-saving against an EF Core `DbContext`:

```csharp
using MapsterMapper;
using SlimMessageBus.Host;
using SlimMessageBus.Host.Memory;
using SlimMessageBus.Host.Serialization.SystemTextJson;

builder.Services.AddSingleton<IMapper>(new Mapper(new TypeAdapterConfig()));
builder.Services.AddDbContext<AppDbContext>(o => o.UseSqlServer(connectionString));
builder.Services.AddScoped<DbContext>(p => p.GetRequiredService<AppDbContext>());
builder.Services.AddSpecRepo<AppDbContext>();                 // DKNet.EfCore.Specifications

builder.Services
    .AddSlimBusEfCoreInterceptor<AppDbContext>()               // auto-save after a successful write
    .AddSlimMessageBus(mbb => mbb
        .AddJsonSerializer()
        .AddServicesFromAssembly(typeof(Program).Assembly)     // discovers generated + hand-written handlers
        .AddChildBus("Memory", mb => mb.WithProviderMemory().AutoDeclareFrom(typeof(Program).Assembly)));
```

## Target developer experience

```csharp
// Domain project — the ONLY hand-written feature code
public class Product : Entity
{
    [CrudCreate]
    public Product(string name, decimal price) { ... AddEvent<ProductCreated>(); }

    [CrudUpdate]
    public void UpdatePrice([Range(0, 1_000_000)] decimal price) { ... AddEvent<PriceChanged>(); }
}

// API project
[GenerateDto(typeof(Product))]
public partial record ProductDto;                             // existing generator

app.MapGroup("/products").MapProductCrud<ProductDto>();       // generated extension
```

## Features

### Discovery — `[CrudCreate]` / `[CrudUpdate]`

Both attributes live in `DKNet.EfCore.Abstractions` (the domain layer already references it; no messaging
dependency leaks in):

- `[CrudCreate]` — on a public constructor or method. At most one per entity (`DKCRUDGEN003` otherwise).
- `[CrudUpdate]` — on any public instance method; one generated request per marked method.
- Both accept an optional `Name` to override the generated request name (default:
  `Create{Entity}Request` / `{MethodName}{Entity}Request`).
- Delete needs no attribute — `MapDeleteById` already covers it generically for every entity.

The generator scans **both the compiling project and its referenced assemblies** — an entity in a separate
`Domain` project is discovered from the API project without redeclaring anything.

### DTO resolution — `[GenerateDto]`

The generated requests' `IWitResponse<TDto>` needs a concrete DTO type, resolved at *generation* time by
scanning the compiling project for the partial record marked `[GenerateDto(typeof(TEntity))]` (the existing
`DKNet.EfCore.DtoGenerator` attribute). Exactly one match is required — zero (`DKCRUDGEN001`) or more than
one (`DKCRUDGEN002`) is an error, since the domain-side attribute can't itself reference an API-layer type.

### Request records

Per marked member, a `sealed partial record` with a `Request` suffix:

- Properties mirror the member's parameters (PascalCase names, original types).
- `System.ComponentModel.DataAnnotations` attributes on the parameters (`[Required]`, `[Range]`, …) are
  copied onto the generated properties — see [Validation is metadata, not enforcement](#validation-attributes-are-metadata-not-enforcement).
- `[CrudCreate]` → implements `Fluents.Requests.IWitResponse<TDto>`.
- `[CrudUpdate]` → implements `IWitResponse<TDto>` **and** `IWithKey<TKey>` (an `Id` property bound from the
  route).

### Handlers

Each request also gets an `internal sealed IHandler<TRequest, TDto>` in `{Entity}CrudHandlers.g.cs`:

- **Create**: invokes the `[CrudCreate]` constructor/method with the request's values, then
  `IRepositorySpec.AddAsync`.
- **Update**: fetches the entity via a generated by-id specification; missing → `Result.Fail` wrapping
  `NotFoundError` (mapped to HTTP 404); found → invokes the `[CrudUpdate]` method.
- Both return `mapper.ResultOf<TDto>(entity)` — the DTO materializes lazily, after the SlimBus EF Core
  auto-save interceptor has persisted the change, so DB-generated values (identity keys, timestamps) are
  present in the response.

### Endpoint registration — `Map{Entity}Crud`

```csharp
app.MapGroup("/products").MapProductCrud(o => o.Exclude(CrudOp.Delete));
```

A non-generic `Map{Entity}Crud(this RouteGroupBuilder, Action<CrudMapOptions>? configure = null)`, composing
the **existing** mappers — no new mapping layer:

| Operation | Route | Response |
|---|---|---|
| GET by id | `{id}` | 200 + DTO / 404 |
| GET list (paged) | `/` | 200 |
| POST create | `/` | 201 + DTO body (`Location` header currently a placeholder, `/`) |
| PUT — first `[CrudUpdate]` | `{id}` | 200 + DTO body / 404 |
| PUT — additional `[CrudUpdate]`s | `{id}/{kebab-case-method-name}` | 200 + DTO body / 404 |
| DELETE by id | `{id}` | 200 / 404 |

Additional `[CrudUpdate]` methods route in declaration order: the first keeps the plain `{id}` PUT, each one
after gets its method name kebab-cased onto the route (`UpdatePrice` → `{id}/update-price`).

`CrudMapOptions.Exclude(params CrudOp[])` (in `DKNet.AspCore.Extensions`) skips the named operations
entirely — nothing is registered for them, not merely hidden.

#### Endpoint emission is opt-in

`{Entity}CrudEndpoints.g.cs` is only generated when the compiling project references
`DKNet.AspCore.Extensions`. A project that wants only requests/handlers (no ASP.NET Core dependency) gets
exactly that, instead of a file full of unresolved types.

### Validation attributes are metadata, not enforcement

DataAnnotations copied onto a generated request are metadata only — minimal API does not run DataAnnotations
validation on its own. `[Range(0, 1_000_000)]` above rides along on `UpdatePriceProductRequest.Price`, but
nothing rejects an out-of-range value at the HTTP boundary until you add your own validation (e.g.
FluentValidation + a SharpGrip AutoValidation endpoint filter) against the generated request type.

### Overrides — hand-written handlers win

If the compiling project already declares a type implementing `IHandler<TRequest, TDto>` for a generated
request, the generator skips that request's handler and reports `DKCRUDGEN005` (Info) at the hand-written
type — the request record is still generated. Matching is by the **request type's name only**; the
hand-written type's response/DTO type argument is not cross-checked against the entity's resolved DTO, so
get it right by hand.

Per-operation exclusion at *mapping* time is a separate mechanism — see `CrudMapOptions.Exclude` above.

## Diagnostics

| Id | Severity | Meaning |
|---|---|---|
| `DKCRUDGEN001` | Error | Entity has `[CrudCreate]`/`[CrudUpdate]` members but no `[GenerateDto(typeof(Entity))]` DTO was found in the compiling project. |
| `DKCRUDGEN002` | Error | More than one `[GenerateDto(typeof(Entity))]` DTO exists for the entity in the compiling project. |
| `DKCRUDGEN003` | Error | More than one member on the entity is marked `[CrudCreate]`; only one is allowed. |
| `DKCRUDGEN004` | Error | A member marked `[CrudCreate]`/`[CrudUpdate]` is not public. |
| `DKCRUDGEN005` | Info | A hand-written `IHandler<TRequest, ...>` was found for a generated request; the generated handler was skipped. |
| `DKCRUDGEN006` | Error | The entity does not implement `DKNet.EfCore.Abstractions.Entities.IEntity<TKey>`. |

## Composition with other DKNet packages

- **`DKNet.EfCore.Abstractions`** — home of `[CrudCreate]`/`[CrudUpdate]` and `IEntity<TKey>`, which every
  CRUD-attributed entity must implement (`DKCRUDGEN006`).
- **`DKNet.EfCore.DtoGenerator`** — the source of the `[GenerateDto]` DTOs this generator resolves against.
- **`DKNet.EfCore.Specifications`** — `IRepositorySpec` and `Specification<TEntity>`, used by every generated
  handler.
- **`DKNet.SlimBus.Extensions`** — the request/handler contracts, `NotFoundError`, LazyMapper, and the
  auto-save interceptor that persists what the handlers change.
- **`DKNet.AspCore.Extensions`** — the entity and bus endpoint mappers (`MapGetById`, `MapGetList`,
  `MapDeleteById`, `MapPost`, `MapPutById`) the generated `Map{Entity}Crud` composes, plus `CrudMapOptions`.

## Out of scope (by design)

- FluentValidation integration — revisit only if DataAnnotation copying proves insufficient.
- Generated domain events, event handlers, or Mapster configs.
- `dotnet new` scaffolding templates — nothing editable is emitted, so nothing drifts.
- PATCH/partial-update semantics.
